## 3. 首版发布门槛

### 用户流程

- 创建者从空任务开始，经发布、复制给 AI 的接入说明、修改独立网页、外部网页提交，到查看和导出全过程通过真实浏览器验证；首次引导以此路径为主（产品评审 D3 已确认 A）。记录从创建任务到首条外部网页提交在后台可见的耗时、是否使用开发者帮助及超时失败点。
- 公开填写页在手机宽度下可完成必填、选项、报错、重试和成功流程。
- 控制台展示测试记录与正式记录的区别，默认统计及导出不混入测试记录。
- 任务关闭、到期、达上限时，用户收到可理解提示。
- 默认入口按累计正式接收区分：无正式接收到接入说明，曾有正式接收到数据；测试不触发切换、删除全部正文不退回引导、区域链接不被改道、当前操作不被首条记录打断（D10 已确认 A）。
- 字段配置的选中项、设置和填写预览一一对应；改字段及上下移动同步反映到预览，预览不创建提交（D11 已确认 A）。
- 请求中及结果未知时锁定本次内容，重试沿用原 key/原快照；明确字段拒收后可修正，确认成功显示回执，不能悄悄另发一份（D12 已确认 A）。

### 数据及权限

- 所有管理端资源查询包含拥有者校验；跨账号读取、导出、编辑、删除均失败。
- 公开 ID 只允许提交；GET、猜测管理 ID 及改参数都不能取得提交内容。
- 幂等 key 的并发重复提交只产生一条记录；请求取消后重试能够取得已持久化回执。
- 提交数配额在并发情况下仍生效；正式提交与累计成功接收数同事务持久化，删除不释放名额，幂等重试不重复占额；服务重启不丢失已确认记录（D4 已确认 A）。
- 单条删除移除业务正文，保留最小幂等记录；删除与原 key 重试按两个完成顺序验证，均不得重建正文、重复占额或在列表/导出中恢复该内容；直接检查数据库不再保留完整 payload（D6 已确认 A）。
- 登录管理端使用会话安全设置及 CSRF 防护；用户内容按文本渲染；日志不写入密码和完整提交正文。
- 速率限制、请求体限制和分页均在服务器执行，不能仅靠界面限制。
- 数据库集成、事务及并发验收使用 PostgreSQL，开发、预发布及线上保持同一数据库种类；不能用 SQLite 测试替代发布数据库验收（D5 已确认 A）。

### 初始容量目标

规划基线为单任务 10,000 条记录、典型 payload 不超过 10 KB，模拟 50 个独立客户端同时提交。普通列表固定每页 50 条。请求上限暂定 64 KB，待试用样例核对。

这些数字是工程评审保留的待实测目标，不是源码支持能力或已经测得的结果。压测必须记录环境、延迟和错误率；目标为无漏写、无重复写，在正常配额下无服务端错误，写入 P95 小于 2 秒。测不达标先调整实现或降低公布容量，不对外声称已支持。

### 运维和试用

- 在预发布环境实际完成一次备份、删除测试环境数据、从备份恢复的演练。
- 部署失败可回到上一应用版本；涉及不可逆数据库变更时单独设计恢复流程，不能把回滚简化成切换代码。
- 至少一位非开发者完成一次真实收集并反馈，记录其接入耗时及失败点。
- 启动后验证健康、登录、创建测试任务、真实提交、导出和日志；测试成功后清理测试记录。
- 部署目标、域名和费用尚未确定；本轮不创建云资源或执行发布。

## 5. 风险与处理

| 风险 | 处理及触发点 |
|---|---|
| 误把“类似 QuickForm”理解成完整问卷设计器 | 阶段 0 明确主场景；复杂跳题、计算、分支和布局不进入 P0 |
| 公开仓库不等于完整在线版 | 核对本地模板和引用资源，不承诺直接启动或完整复刻线上能力 |
| 浏览器公开地址被当成秘密令牌 | 分离读写、服务端限流和总量配额；高风险场景另加验证，不声称可以防代填 |
| 字段修改导致历史记录难以解释 | 首次发布锁定 key 和类型；结构变化复制任务 |
| 开发和发布数据库环境不同，导致并发问题晚发现 | 开发、集成测试、预发布及线上统一 PostgreSQL；从阶段 1 开始在该数据库上验收（D5 已确认 A） |
| AI 报告耗时或供应商失败阻塞收集 | 先交付无 AI 的闭环；后续报告独立运行、记录失败、可重试 |
| 任意 HTML 或附件导致权限和执行边界扩大 | 首版不开放；新阶段先做隔离设计，再实现上传及预览 |
