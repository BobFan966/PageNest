## 1. 产品定位

帮助教师、活动组织者和个人开发者，将现有网页或 AI 生成页面中的数据集中收集、查看和导出。

第一版先服务一个具体场景：教师创建一次课堂练习收集任务，将接入说明交给 AI，为交互页面加入提交功能；学生打开页面完成练习，教师在后台看到结果并导出。

已确认首次使用优先验证“教师的 AI 网页数据接入和收集后台”（2026-10-24，产品评审 D3，选择 A）。简单填写页保留为预览和另一收集入口。完整问卷设计器不进入首版。

### 成功标准

- 创建者能在 10 分钟内从创建任务走到独立网页的第一条真实提交在后台可见，无需自己编写后端；记录是否使用开发者帮助，超时也记录。系统填写页成功不能替代外部网页接入验收。该时间是试用目标，尚非测量结果。
- 同一个任务支持系统生成的填写页，以及独立网页通过 API 提交，两种入口汇总到同一数据列表。
- 页面收到成功响应时，记录已经持久化；服务重启后仍可查看和导出。
- 至少两名创建者的数据相互隔离，公开提交地址不能用于读取提交内容。
- 一次真实小范围试用完成“创建、接入、提交、查看、导出、关闭收集”全过程。

## 3. 用户和使用流程

| 角色 | 第一版权限 |
|---|---|
| 创建者 | 登录、管理自己的任务、查看自己的数据、导出、关闭收集 |
| 填写者 | 无需注册，通过公开填写页或外部页面提交；不能查看其他提交 |
| 站点维护者 | 通过受控运维方式创建试用账号、禁用账号、查看服务状态；暂不开发完整运营后台 |

第一版采用少量受控账号，不开放公众自助注册。账号隔离从第一版开始做，但组织、班级、成员协作和复杂角色后置。

主流程：登录 → 创建任务 → 配置字段 → 预览 → 开启收集 → 复制给 AI 的接入说明 → 外部网页加入提交功能 → 填写者提交 → 创建者查看和导出 → 关闭收集。系统生成的填写页保留为另一收集入口。

## 4. 第一版必须实现的需求

| 编号 | 能力 | 范围及验收 |
|---|---|---|
| R01 | 账号和隔离 | 登录、退出、修改密码；所有任务、提交、导出操作都检查归属；A 账号不能通过改 URL 或请求参数读取 B 的数据 |
| R02 | 任务管理 | 标题、说明、创建时间；草稿、收集中、已关闭三种状态；支持编辑说明、复制任务；草稿及关闭状态拒绝公开提交 |
| R03 | 简单字段配置 | 单行文本、多行文本、数字、单选、多选五种类型；字段 key、显示名称、必填、选项及适用长度/数值限制；上移下移即可，不做复杂拖拽 |
| R04 | 填写页 | 根据字段生成移动端可用的填写页；必填和类型提示；提交中防重复点击；成功回执；失败保留输入并可重试 |
| R05 | 外部网页接入 | 接受 JSON 对象及普通表单编码；提供复制即用的 fetch 示例、示例数据及给 AI 的接入说明；控制台能发起测试提交，并与正式记录区分 |
| R06 | 数据查看 | 总数、按时间分页、字段列及单条详情；按时间范围过滤和简单关键词搜索；空数据、错误、加载状态有明确提示 |
| R07 | 数据导出 | CSV 和 JSON；默认导出当前筛选范围；显式选择全部；CSV 中文可正常打开，处理公式注入；导出仅限任务拥有者 |
| R08 | 收集控制 | 随时关闭/恢复、设置截止时间和累计成功接收的正式提交上限；删除不释放名额，同一逻辑提交重试不重复占额；达到上限提示“已达到累计接收上限”，拥有者可提高上限；继续接收新提交仍须满足任务开启且未到期；错误响应区分关闭、到期、限流及数据不合法（D4 已确认 A） |
| R09 | 数据删除 | 拥有者可确认后删除单条提交正文；删除减少当前记录数，不减少累计接收数；保留最小幂等记录，旧 key 同内容重试返回原回执且不重建正文，不同内容仍冲突；首版不提供一键清空全部数据及永久删除任务，避免扩大恢复和审计范围（D6 已确认 A） |
| R10 | 可靠性和运维 | 服务端校验、提交幂等、事务持久化、请求大小限制、速率限制、错误日志、健康检查、备份及一次恢复演练 |

字段策略：外部网页也使用任务声明的字段。第一次发布后锁定字段 key 和类型，可修改标签、说明；结构性变更通过复制任务处理，防止历史数据与新表单冲突。额外字段返回明确校验错误，不静默丢弃。无 schema 的任意事件流收集可后续单独扩展。

## 5. 页面范围

1. 登录页。
2. 工作台：任务列表、状态、提交数、创建入口。
3. 任务创建/编辑页：基础信息、字段配置、预览、发布。
4. 任务详情页：概览、接入说明、数据、设置四个区域；区分“当前记录数”和“累计接收数/上限”，避免删除后计数含义混淆（D4 已确认 A）。
5. 公开填写页和提交结果状态。
6. 账号设置页：修改密码。

任务默认入口（D10 已确认 A）：从工作台进入已发布任务时，累计正式接收数为 0 默认显示接入说明，累计数大于 0 默认显示数据。测试记录不触发默认入口切换；删除全部正文后仍显示数据。四个区域始终可切换，明确指向某区域的链接仍到该区域；收到首条记录时不强制打断用户当前操作。默认到数据仅表示曾有正式接收，不等于已经验证独立网页接入成功，外部接入仍按 D3 真实核验。

字段配置布局（D11 已确认 A）：桌面主编辑区显示字段列表及选中字段的设置，旁边显示填写预览。列表给出名称、类型和必填摘要，支持添加和上下移动；设置只展开当前类型适用的选项/限制，选中字段与设置一一对应，字段及顺序变化同步反映到预览。预览不产生真实或测试提交。具体窄屏布局及可访问性在设计 Pass 6 明确；字段 key 默认生成和发布确认交互不由本项决定。

提交结果未知的交互（D12 已确认 A）：发出请求时固定本次内容快照与 submission_key；请求中及结果未知时，当前这次提交的内容不可修改。“重试确认”始终使用原 key 和原快照，不静默另发一份。界面明确提示“暂时无法确认是否收到，本次内容已保留，请重试确认”；确认成功显示原回执，服务器明确拒收并指出字段错误后才允许修正。本项只确定当前页交互，不新增学生账号、离线队列或页面刷新后的恢复能力。

首版后台以桌面使用为主；公开填写页必须适配手机。暂不建设营销官网、模板商城或复杂首页。

## 6. 接口和数据约定草案

以下是新产品的接口草案，不承诺与 QuickForm 原接口完全兼容。

- 公开提交：`POST /api/v1/collect/{public_id}`。public_id 用于标识开放收集入口，不是保密凭据；第一版不允许通过此地址查询记录。
- 管理端读取、编辑、导出：独立的登录接口，逐次校验任务归属。CORS 仅用于限制浏览器接入，不代替认证或反滥用措施。
- 任务开启前配置接入来源；填写页同源提交，外部页面允许配置多个具体 HTTPS 来源；本地调试显式允许 localhost 来源。不支持任意 file:// 接入。
- 提交数据统一为字段对象；系统生成 submission_id、服务端接收时间和 schema 版本标识，系统字段不接受调用者覆盖。
- 外部页面为每次逻辑提交生成 submission_key，网络失败重试复用同一 key；数据库以任务和 key 唯一约束，重复请求返回原回执。同 key 不同数据报冲突，不覆盖原记录。
- 删除业务正文时，保留任务、原 key、内容指纹和原回执所需的最小元数据，随任务生命周期保留；不保留完整 payload。原回执确认历史请求曾成功，不代表正文仍被后台保留；旧请求不能使已删除内容重新出现或再次占额。存储结构已按工程 E2 确认，内容一致性已按 E3 确认，摘要算法按工程 E4 细化（D6 已确认 A）。
- 明确区分：成功、格式错误、字段校验失败、任务关闭/到期、请求过大、频率超限、服务器错误。数据库写入成功后才返回成功。
- public_id 泄露后仍可能被程序滥用，因此需要任务关闭、总量配额和服务端限流；复杂验证码根据试用情况再增加。
- 第一版不强制收集姓名、手机号；身份关联优先使用创建者定义的参与者代号。公开收集页提供用途说明。不自动把 IP 保存为业务字段。

主要实体：User、Task、TaskField、Submission。Task 包含 owner、public_id、状态、截止时间、配额、累计成功接收数、schema 版本；累计成功接收数与正式提交写入在同一事务更新，不因单条删除回退。Submission 包含任务、payload、幂等 key、接收时间、测试标记。AI、文件和组织暂不创建占位业务体系。

工程并发机制（E1 已确认 A，2026-10-28）：采用 PostgreSQL READ COMMITTED 与按 Task 行加锁。同任务收集、关闭/恢复、截止/配额变更及正文删除统一先锁 Task，再读写相关提交；不同任务没有应用全局锁。锁后读取最新状态，先处理已有 key 的原回执/内容冲突，再判断新提交是否可接收。正文、幂等元数据和累计数在同一事务提交，失败整体回滚；锁内不进行网络或导出。数据库保留任务+key 唯一约束，等待与执行设置有界超时，失败不返回成功，重试复用原 key。取得锁后以实际时刻判断截止，不能使用开始排队前的旧时间。具体验证包含最后名额、同 key 并发、关闭/删除与重试两种顺序、失败回滚及等待跨截止；尚未实现或运行这些测试。

工程删除存储（E2 已确认 A，2026-10-28）：同一 Submission 行保存可清除的 payload 和必要接收元数据。删除沿用 E1 事务与锁顺序，将 payload 置为 SQL NULL、记录删除时间；保留任务、原 key、指纹及算法版本、原 submission_id、原接收时间、schema 版本、服务端测试/正式标记等去重与原回执所需元数据，不保留完整响应副本。数据库约束未删除行有对象正文、已删除行无正文，任务+key 唯一约束仍有效。列表、详情、搜索、当前记录数及导出共用未删除记录查询；幂等查询包含已删除凭据，同内容返回不含正文的原回执，不同内容冲突，不补回正文或增加累计数。验收检查当前业务表正文已清除及各读取路径不可见、旧 key 不复活、删除/重试的两个完成顺序；备份历史的保留与恢复处理仍待运维评审。

工程内容一致性（E3 已确认 A，2026-10-28）：JSON 与普通表单先按字段契约解码/校验，再对规范字段对象计算指纹。对象键顺序、JSON 排版和等值数字表示不导致内容冲突；文本保留原字符，不自动去空白或改大小写。多值表单不得丢弃选项；不合法类型、重复 JSON 键和非有限数值明确拒绝。保留规范化版本，删除正文后仍能验证原请求。详细空值、数值精度及多选规则见工程编码契约，必须有跨格式对照测试。

工程细节授权（2026-10-28）：用户要求小型实现问题由评审者自行选择，不再逐项询问；已确认的 E1—E3 不变。以下技术细化属该授权，尚非实现或运行结果：

- 指纹使用服务端 HMAC-SHA256，绑定任务、原 key、schema/规范化版本与规范内容，保存算法版本及 key_id；密钥独立于数据库和会话密钥管理。旧指纹对应旧密钥必须保留，缺密钥时拒绝处理而不能当成新提交；不把摘要当作匿名化保证。
- 控制台测试走拥有者专用管理写接口，登录、归属和 CSRF 检查齐全；服务端设置测试标记，公开请求不得伪造。测试使用相同解析/校验/幂等规则和独立命名空间，不增加正式累计数，列表/导出默认排除；允许草稿测试，不构成正式收集成功；测试绑定草稿revision，结构改变后旧测试重试返回schema_changed，提示新一轮测试使用新key，正式重放保证不变。
- 首次发布冻结校验结构，包括字段 key、类型、必填、选项、长度/范围规则及结构版本；仅标签、说明等展示文案可变。结构调整使用原定复制任务。这样旧请求不会因后来更严格的规则而无法取得原回执。
- 多进程限流统一在单个 Nginx 入口的共享限流区执行；WSGI 仅内网可达。任务级与来源 IP 的宽松突发保护、登录保护分别配置，避免一间教室共享 IP 被错误限流。应用内存计数不承担全局限流。此方案只支持单入口；多入口部署必须先补共享限流机制。
- 导出采用同筛选快照、完整临时文件后下载，全站最多1份且使用同应用独立受限worker池。账号、查询、编码及导出细化见评审文档；E8已确认灾难事故RPO≤1小时、RTO≤4小时，普通重启仍不丢已确认数据。采用独立加密基备份/WAL归档，隔离恢复后核对删除/幂等/累计数；无法核对的旧任务保持封存、新收集复制任务。恢复目标和安全核验未通过演练前，不得把阶段4标为可以上线；具体流程见工程E8。

| A. 教师版直接改造 | 现成登录、任务、收集和导出，最快本地验证 | 单文件耦合较重，公开读取、上传、隔离及模板完整性要重新核对；上线返工风险较高 | 目标是个人本地演示 |
| B. 参考源码，新建模块化单体（已确认） | 保留已证明的任务/API 模型，明确新产品权限和数据契约，适合逐步发布 | 基础页面和账号流程需要重建，起步工作多于 A | 目标是可让少量用户真实使用的网站 |
| C. 现成托管表单/数据库服务加定制前端 | 可以较快验证收集需求，减少初期运维 | 接入、存储、成本和迁移受平台约束；平台能力尚未调研 | 优先验证需求，允许使用外部服务 |

已确认路线 B：参考源码，新建模块化单体。具体实现建议沿用 Python/Flask、SQLAlchemy 和服务端模板，按账号、任务、收集、导出划分模块，前端仅在字段编辑等必要位置增加交互。开发、数据库集成测试、预发布和线上统一使用 PostgreSQL（2026-10-24，评审 D5 已确认 A），通过数据库迁移管理结构；无数据库的纯校验单元测试无需启动数据库。数据库安装方式、数据库及框架版本、托管平台与费用在后续工程评审/实施时确认，当前不做版本或价格承诺。
