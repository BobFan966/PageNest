# QuickForm 首版交互与验收规范

日期：2026-10-29。状态：设计方案已审；等待正式实现及验收。

依据：`requirements-v0.1.md`、`development-plan-v0.1.md`、`review-v0.1.md` 与根 `DESIGN.md`。用户授权“这些简单的都由你决定好了”，本轮在原定 P0 范围内确定 D13—D23。该授权不包括付费、部署、调整数据损失目标或开发新业务功能。

## 1. 页面主次与用户旅程

```text
登录 → 我的任务 → 创建任务/配置字段 → 预览/发布 → 接入说明
                                                    │
                         复制说明 → AI修改独立网页 → 外部真实提交
                                                    │
                 关闭/截止/累计名额 ← 设置     核对记录 → 查看/导出
```

四个任务区域始终可达；按 D10 选择默认入口，不强制切走当前页面。字段编辑沿用 D11 的列表/设置与预览分区；未知结果沿用 D12 的原内容/原 key 重试。页面最多突出一个主要动作。预览中的设计页侧栏不作为产品导航照搬。

| 步骤 | 用户动作 | 预期感受 | 页面支持 |
|---|---|---|---|
| 登录/首次进入 | 使用受邀账号登录 | 知道这是自己的工作空间 | 无自助注册广告，空工作台主动作“创建收集任务” |
| 配置字段 | 选择类型、规则和顺序 | 看得懂、改动有反馈 | 当前字段高亮，旁边填写预览；移动后保持焦点 |
| 发布 | 核对标题、字段、来源与接收条件 | 明白发布后锁定哪些规则 | 确认摘要与显式发布按钮；校验失败保留草稿 |
| 接入 | 复制说明并交给 AI | 下一步明确 | 接入地址、字段、示例、来源与重试规则一起提供 |
| 首次核对 | 在独立网页提交并看记录 | 用实际结果建立信心 | 对照参与者代号、值和接收时间；测试不冒充正式成功 |
| 日常查看 | 筛选、翻页和查看详情 | 容易找到数据 | 当前保留、累计接收和筛选匹配数分别标明 |
| 导出 | 选择范围与格式，发起下载 | 知道导出的范围与下载状态边界 | 原生浏览器下载，失败有返回入口，不声称已保存到磁盘 |
| 停止/返回 | 关闭或处理到期/满额 | 清楚还能不能继续收集 | 全部实际阻塞原因及相应管理入口 |

时间尺度：首次五秒识别任务与主动作；五分钟内能理解配置、接入和核对的顺序；长期复用依靠稳定字段含义、可解释计数及可靠回执。十分钟接入是待真实试用测量的目标，不是已测结果。

## 2. D13：有效接收状态

采用 A：先显示“可接收新结果”或“当前不接收新结果”，再列出全部成立原因：草稿未发布、手动关闭、已到截止时间、累计名额已满。拥有者分别看到发布/恢复收集、修改截止时间或提高上限入口；填写者只有状态、原因与“联系任务创建者”的文字，没有管理链接。

恢复开关只改变人工状态，不能覆盖截止或累计上限；处理一项后仍显示其余原因。字段结构冻结不因恢复而解除。旧请求仍先按幂等契约取得历史回执，该状态限制的是新提交。

验收：覆盖关闭/到期/满额的全部八种组合、草稿拒收；逐项解决仍保留未解决原因，全部满足才显示可接收；公众看不到管理入口。

## 3. D14：字段编辑、默认 key 与发布

新字段默认使用 `field_1`、`field_2` 等当前草稿中未使用且非系统保留的标识；显示名称可自由填写，改名称不自动改 key。发布前可显式编辑 key，旁边说明其用途；校验空值、重复和系统保留名。创建者可使用 `score` 等有意义的标识，无需把中文自动转拼音或引入 AI 命名。

字段列表显示名称、类型、必填与上下移动；键盘可选中字段。类型变化若将丢弃已配置的选项/规则，先就近确认，再更新设置与预览。五种类型只显示适用约束；数字零不被识别为缺失，多选不丢选项。预览不产生提交。

发布前显示标题、字段数、接入来源、截止时间/时区、累计上限及锁定说明；未设置的可选项显示“未设置”，不伪造默认限制。首次发布冻结 key、类型、必填、选项与校验规则；标签和说明仍可改，结构变化使用“复制为新任务”。已发布页面显示锁定原因和复制入口，不只把控件变灰。

保存/发布中显示具体操作并防重复点击；失败保留全部输入。发布响应未知时保留草稿副本，先“核对发布状态”；按同一个任务 id/revision 查询服务端状态，不另建任务。revision 冲突保留本地副本供手工比对，不覆盖服务器新版；结构变化后旧控制台测试显示“字段已变更，请重新测试”，新测试使用新 key，旧请求不改内容重发。

验收：名称变化不改 key；重复/保留名不能发布；五种类型及顺序与预览一致；两标签页保存/发布冲突不覆盖；发布失响应可确认；锁定范围与 E7 一致。

## 4. D15：列表、筛选与空状态

| 状态 | 用户看到什么 | 主要动作 |
|---|---|---|
| 首次无任务 | “还没有收集任务”，说明创建后可接入网页 | 创建收集任务 |
| 未接入，无正式接收 | “还未收到正式记录”，说明接入和实际核对步骤 | 查看接入说明 |
| 只有控制台测试 | “目前只有测试记录”，正式数为零，测试明确标注 | 继续网页接入 |
| 筛选无结果 | “没有符合条件的记录”，保留筛选条件 | 清除筛选 |
| 曾收集、正文已全部删除 | 当前记录为零，累计数保持不变；不退回首次接入 | 查看接入说明/调整已有收集设置 |
| 初次加载 | 表格区域“正在读取”，数量尚未取得 | 等待；不显示伪造的零 |
| 刷新已有列表 | 保留旧行并标“正在更新/上次读取”，禁止依赖旧值的写入 | 等待本次读取 |
| 读取失败 | “暂时无法读取”，数量未知；旧行若保留明确标过期 | 重试，保留筛选 |

列表区分任务当前保留数、累计接收/上限和当前筛选匹配数。默认只看正式数据；切换测试范围始终有文字标记。每页五十条，按接收时间及 id 稳定排序；筛选变化回第一页。用户输入用文本渲染，长内容省略处有详情入口，详情保留换行，空值与数字零有不同显示。

时间筛选显示时区，使用工程已定的左闭右开区间；日期形式的结束日期在查询层换算为次日开始并明确“包含该日”。收到新数据不自动改筛选、翻页或打断阅读；重新加载后更新，不要求增加实时推送。

## 5. D16：导出范围、结果与失败

数据页提供就近展开的导出设置：CSV/JSON、默认“当前筛选”、显式“全部正式记录”；显示任务、筛选与正式/测试范围。普通列表分页不限制导出范围，不把当前页五十条当全部。匹配零条时明确显示零条，可生成仅表头 CSV 或空数组 JSON，不声称含有数据。

沿用工程 P1 同筛选快照、完整临时文件后发送、全站一份活动导出，不新增队列、后台任务中心、下载令牌表或前端大 Blob 缓存。首版由用户点击后向原生浏览器发起下载，目标为单独同源结果页/命名标签页，保留原筛选页面；界面提前说明“将通过浏览器下载；若失败，请查看结果页”。失败响应在该结果页呈现可读说明与返回原任务数据页的入口，不把 JSON 错误当成数据文件。

原页面只说“下载请求已发起，请查看浏览器下载列表”，不说“下载完成”或“已保存到电脑”。结果页能确认服务端失败；无法观测的客户端中断由浏览器下载列表反馈，允许在浏览器确认失败后按相同条件重新发起。不得为了进度条把整份文件一次性加载到前端内存。

忙时显示“当前有导出正在进行，请稍后重试”，不泄露其他用户/任务；生成失败、超时、空间不足不发送成功下载头，传输中断不宣称完成。CSV/JSON 文件的快照时间与行数由服务器生成并随既有下载响应提供；页面的更晚实时数量不冒充导出快照数。新提交不加入已固定的快照，快照后的删除不会撤回该次授权导出；发起前用简短说明告知这一范围。

验收：当前筛选与全部、测试/正式、零条、并发导出忙、服务器生成失败、客户端下载中断与重试；真实文件内容、编码与快照一致。原生下载及错误页需在真实浏览器端到端验收。

## 6. D17：删除正文确认与结果未知

单条详情使用“删除这条正文”，确认对话框标识记录代号和接收时间，并说明：“正文删除后无法从后台恢复；系统保留必要去重信息；累计名额不恢复。”这不承诺历史备份即时清除，备份保留/恢复仍按 E8。默认焦点在取消，危险操作按钮使用明确文字，不新增批量删除、撤销或回收站。

请求中禁用重复删除；收到成功响应后才移除行并更新当前数/筛选数，累计数保持。失败保持原行与原筛选。失响应时标“暂时无法确认删除结果”，不乐观移除；通过拥有者列表/详情重新核对。记录已不可见只能说明“当前列表中已无该记录”，不能推断是本次删除完成；无权/不存在不泄露他人记录。确认后焦点回到下一条可操作记录或列表标题。

## 7. D18：接入来源与首次成功

接入说明中先呈现下一步，再给地址、字段、样例和给 AI 的说明。任务设置中的允许来源配置沿用原需求：多个具体 HTTPS origin；本地调试可显式配置 localhost origin；拒绝通配符、路径当 origin、null/file 来源。输入旁给 `https://class.example.edu` 的格式示例，报错保留输入，不把 public_id 描述成密码。

同源填写页不要求教师再手动添加同源地址。控制台测试需要登录和归属检查，不模拟外部浏览器来源成功。只有用户在独立网页真实提交并核对代号、值和接收时间，才完成首次接入验收；来源没有可信服务端证据时不自动认证“该记录一定来自外部网页”。复制失败允许选中文字手动复制，不能显示“已复制”。

## 8. D19：填写与回执的完整反馈

| 情况 | 页面反馈与动作 |
|---|---|
| 必填/字段错误 | 顶部错误摘要 + 字段旁提示，定位首个错误，保留全部输入 |
| 正在提交 | “正在提交…”，防重复点击，固定本次内容/key |
| 成功/同内容重放 | “已确认接收，无需重复提交”，显示回执号和接收时间；不承诺后台仍保留正文 |
| 断网、超时或服务端结果不确定 | D12 只读原内容，“重试确认”；成功后仍是原回执，不静默换 key |
| 明确字段拒收 | 解锁可修正字段，保留内容；按原协议修正后重试 |
| 同 key 不同内容冲突 | 不覆盖原记录，不自动新建；提示此次内容不一致，联系创建者核对 |
| 明确限流 | 保留内容/key，依据服务端重试提示稍后确认，不出现成功图示 |
| 关闭/到期/满额 | 显示 D13 全部实际原因；未确认请求仍保留其重试确认路径 |
| 草稿结构已变化的私有测试 | 提示新一轮测试；不把旧测试自动变为正式提交 |

当前页的只读保护和快照不是跨刷新恢复能力。未知状态离开/刷新前给浏览器支持的离开提醒，并在页内写明“请先重试确认；离开页面可能无法继续确认本次提交”。不新增本地持久化答案、离线队列或学生查询接口。公开填写页无“再次提交一份”的主按钮，避免重复。

## 9. D20：账号与管理会话

受邀账号登录页只有账号、密码、登录与取得账号方式说明，不新增自助注册、第三方登录或邮件找回。输入使用恰当的 autocomplete，允许粘贴和密码管理器；认证失败使用统一说明，保留账号、不回显密码。

管理会话过期显示重新登录入口及未保存提示，不把登录 HTML 当 API 成功。当前标签页尚在的非密码编辑内容可保留，重新登录后先核对服务器 revision 再手工继续，不自动重放发布、删除或导出。无法保留的浏览器导航提前提示可能丢失未保存内容，不宣称跨刷新恢复。改密成功按工程约定重新登录；失败就近报错，不在日志、URL或本地存储保存密码。

## 10. D21：响应式与信息密度

采用 `DESIGN.md` 的 layout token：宽屏左侧导航与主区；中等宽度收窄导航/边距；窄屏横排导航、字段编辑与预览上下排列。任务列表和数据表在有标签的自身区域横向滚动，首列及详情入口可到达，整页不横向溢出。公开填写页独立单列，管理导航不出现在正式公开页。

管理页窄屏先显示任务标题、接收状态和主要动作，再显示计数/筛选/表格；编辑器先列表、后当前设置、再预览，改字段后不自动滚动打断输入。长中文标题、长 key、长反馈与五种字段不能挤走主按钮。按钮在必要时换行，浏览器缩放后文字可重排；不靠禁用缩放修补布局。

验收宽度：三百二十、三百九十、七百六十八、一千零二十四和一千四百四十像素；浏览器放大两倍检查可用性，并对四倍缩放下的表单重排做检查。表格保留二维数据结构的局部滚动，不把它当作整页溢出的理由。

## 11. D22：可访问性与对比度

使用语义化 header/nav/main、层级连续的标题、原生 button/input/select、fieldset/legend 和有作用域的表头。选中导航用 aria-current，字段选择说明选中项；上下移动后焦点跟随同一字段并通过礼貌播报说明位置。表格滚动容器有可读名称且键盘能到达。字段帮助/错误通过 aria-describedby 关联，错误设置 aria-invalid。

普通状态使用 role=status/aria-live=polite；阻断提交的错误摘要及时宣告并允许聚焦，不逐次按键朗读全部表单。对话框打开后焦点在内部、Tab 循环、Escape 可取消、关闭后回触发位置；未知提交的原内容不因解除焦点而变更。长耗时操作标记 busy，不能只留一个无文字转圈。

普通文字对比度至少 4.5:1，大字至少 3:1；必要控件边界和焦点指示至少 3:1。淡分隔线可保持装饰用途，不能成为唯一输入边界。`colors.input-border` 已从风格提案的浅色改为更深的灰绿，维持原风格并满足边界辨识；禁用控件另有文字原因。所有语义色同时使用文案，触控目标采用 `components.layout.touchTargetMinHeight`，支持减少动态效果。

验收必须包括键盘完成登录、建任务/移动字段、发布、筛选、导出发起、取消/确认删除及填写重试；macOS VoiceOver 至少检查公开填写和管理删除确认。预览的 DOM 检查和焦点检查不等同于已完成真实读屏测试。

标准依据（2026-10-29读取）：[W3C 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C 非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。触控目标采用本项目更宽裕的设计要求，不将该尺寸冒称所有 WCAG 等级的统一门槛。

## 12. D23：风格一致性与审阅控件边界

根 `DESIGN.md` 为视觉唯一来源，文案与状态样式引用 `{colors.primary}`、`{colors.text-muted}`、`{colors.warning}`、`{colors.error}`、`{rounded.md}` 和 `{components.layout.mobileBreakpoint}` 等既定 token。全站按钮层级一致，新反馈复用既有提示、表单与详情组件，不创建新的品牌体系。

预览里的“演示状态”“重置”“切换深色”、合成统计和六页审阅导航均是审阅控件。生产页面去掉这些演示入口；只有真实数据才能形成业务统计。不把图像、装饰阴影或嵌套卡片作为首屏主体，不做营销落地页，不新增深色首版需求。

## 13. 实施约束与验收边界

本文件补齐用户可见规格，不实现新后端，不改变 E1—E8。删除、未知重试、正式/测试、导出快照、CORS、账号归属与恢复闸门仍需真实应用测试。源文件与预览都不能代表这些路径已通过。

导出原生下载/同源错误页、发布状态核对及 revision 冲突、会话过期后的编辑保护需要在工程实施前作针对性契约复核；沿用现有路由/事务/临时文件方案，无须重开产品范围，但不能省略相应 E2E 验证。部署位置、域名、预算、试用人数及依赖版本仍是实施准备输入，不属于本轮已解决的视觉决定。
